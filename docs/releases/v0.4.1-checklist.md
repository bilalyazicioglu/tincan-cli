# v0.4.1 release checklist

Audit date: 2026-11-14. Preparation branch: `chore/prepare-v0.4.1`, based on
`develop` at `b3c2939`. This is a release candidate, not a published release.

## Scope and repository

- [x] Mouse controls (#192): channel/person selection, footer actions and audio settings.
- [x] Compact terminal layouts (#193): retain call/audio status and useful controls.
- [x] Terminal-friendly Ctrl shortcuts (#194): invite, talk, mute, push-to-talk,
  deafen and settings; existing F keys remain available.
- [x] Credit @saimskywalker (Setyo Aji Imam Maliki) for #194 in the release notes.
- [x] No open PRs at the audit; all three feature PRs are merged into `develop`.
- [x] Prepare Cargo.toml, Cargo.lock and npm/package.json as 0.4.1.
  Nix reads its version from Cargo.toml.
- [x] Protocol/network code and dependency versions unchanged from v0.4.0.
  Keep `RELAY_MIN_VERSION` at 0.4.0: it is a compatibility threshold.
- [x] Preserve the README corrections already on `main` alongside the new mouse
  and shortcut documentation. Correct `/help` and CLI push-to-talk descriptions.
- [ ] Merge the preparation branch into `develop` through a reviewed PR.
- [ ] Reconcile branch history: `main` has three commits absent from `develop`
  (the 0.4.0 release merge and README PR #187). Preserve those changes when
  preparing the `develop` → `main` release PR.

Reconnect (#175), relay configuration (#179), Termux support and further cosmetic
work (#190) are not release requirements. Issues #53, #188 and #189 are still open
despite the implementation being on `develop`; verify their closure after `main`.

  `cargo clippy --all-targets --locked -- -D warnings` pass on macOS.
- [x] Candidate `cargo test --locked`: **442 passed, 0 failed, 6 ignored**.
  This includes outcome-based UI interaction sequences, compact layouts, stale
  hit targets after resize/roster/hotplug changes, settings actions, text-only
  device failures, admission/chat/roster, voice mesh and a real localhost relay.
- [x] ASCII-mode push-to-talk footer regression passes separately.
- [x] Candidate binary reports `tincan 0.4.1`; `host --help` describes the
  F4/Ctrl+P push-to-talk toggle correctly.
- [x] `node --check npm/bin/tincan.js` and `sh -n install.sh` pass.
- [x] `cargo publish --dry-run --allow-dirty --locked` packages and compiles 0.4.1.
- [x] `npm publish --dry-run --json` produces the 0.4.1 launcher package with its
  README, executable launcher and manifest. Neither dry run publishes a package.
- [x] Existing `develop` CI passes on macOS, Ubuntu and Windows:
  [run 43293700235](https://github.com/bilalyazicioglu/tincan-cli/actions/runs/43293700235).
- [ ] Final preparation/release commit passes the same complete CI matrix.
- [ ] Dispatch `release.yml` on the final candidate branch and verify **all five**
  build/package jobs and their checksums: macOS arm64/x64, Linux arm64/x64,
  Windows x64. Branch dispatch builds artifacts; only a tag publishes.
- [ ] Brief real-terminal acceptance: mouse and Ctrl/F-key actions produce the
  same channel, call, microphone and settings results; compact resize preserves
  the session; selection modifiers still allow terminal copy/paste. Include
  macOS Terminal.app and Ubuntu SSH/byobu; record Windows desktop coverage if
  available. CI does not prove physical audio-device or terminal behavior.

The six ignored tests are two public discovery tests, one BlackHole hardware test
and three media generators. They are not counted as passed. Run the two discovery
tests deliberately before cutting the release if validating live n0 discovery;
do not blanket-run every ignored test, since the generators overwrite assets.
Nix evaluation and the declared Rust 1.91 minimum were not independently exercised
in this audit.

## Publication and download verification

At audit time GitHub, Homebrew, npm `latest` and crates.io all serve **0.4.0**.
No 0.4.1 tag or registry publication was made during preparation.

- [ ] Approve and merge the release PR into `main`; confirm tag `v0.4.1` points
  to that exact tested commit. Publish only after release approval.
- [ ] GitHub release: all five archives **and five matching `.sha256` files**
  exist. Verify the downloaded archive hash and run the extracted binary's
  `--version`; a successful upload alone is insufficient.
- [ ] Homebrew: release workflow updated `bilalyazicioglu/homebrew-tap` to 0.4.1
  with the four correct archive hashes. Verify `brew update`, upgrade/install,
  `tincan --version` and the formula test. Do not silently ignore tap failures.
- [ ] **npm: publish separately after GitHub assets are available.** The workflow
  does not publish npm. Verify `npm view tincan-cli version dist-tags`, then use
  a fresh launcher cache/install to confirm `npx tincan-cli@0.4.1 --version`
  downloads and starts the correct binary.
- [ ] **crates.io: publish `tincan-chat` separately.** The workflow does not
  publish Cargo packages. Verify registry version 0.4.1 and a clean, temporary
  `cargo install tincan-chat --version 0.4.1 --locked --root <temp-dir>`;
  run that installed binary's `--version`.
- [ ] Shell installer: use temporary `TINCAN_INSTALL_DIR` to verify both latest
  and pinned `TINCAN_VERSION=v0.4.1` installations report 0.4.1.
- [ ] Website: verify visible downloads, release links and both languages point
  to the new assets. Audit live `/llms.txt`, `/llms-full.txt` and legacy
  `/tincan/llms.txt`, `/tincan/llms-full.txt` for stale versions and claims.
  **Found:** live `/tincan/llms.txt` still says 0.3.4, 63-character invite codes,
  and self-hosted relays as future work. These need correction in the site repo;
  changing this repository does not deploy that site.
- [ ] Publish [release notes](v0.4.1-notes.md), including contributor credit.
  Confirm issues #53, #188 and #189 are closed appropriately after release.
- [ ] Bring the release changes on `main` back into `develop` through a PR.

Do not mark the release complete until the installed versions and website checks
above pass. Keep a failed distribution step visible and fix it before announcing
that every installation channel is updated.
